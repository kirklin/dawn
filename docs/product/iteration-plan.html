建议结论Recommendation

先交付“看得懂、选得准”的预报体验，再接入“本地/探索”地点路径。随后验证远期数据覆盖，最后建设周边比较和用户共建。首批目录有 15 城、225 个候选；208 个有参考地标坐标，17 个待确认，50 个观赏用途主要是地形推断，所有地点都尚未实地核验。目录整理完成不等于推荐功能已上线。

First make forecasts easy to understand and compare, then add Local/Explore paths. Validate long-range data before building nearby comparisons and community submissions. The catalog has 15 cities and 225 candidates; 208 have landmark reference coordinates, 17 need coordinate review, 50 rely mainly on terrain inference, and none are field-verified. A curated catalog is not yet a live recommendation feature.

0.2 · 看懂一场霞Understand a glow

目前因素卡跟随下一场预报，天空默认跟随当前时间。用户能点选预报，但实时与预览语境不够醒目；折叠场次也容易被误认为更短天数。

  1. 按日期列出朝霞/晚霞，明确“未来 4 天”；覆盖范围和展开状态保持清楚。
  2. 选场后，天空、因素、结论同步到该日期与时刻；显示“预报预览”，可一键回到“现在”。
  3. 从已有模型因素生成规则化综合结论：等级、主要影响、建议。模型分歧或缺测时明确说明。
  4. 增加“值得关注的场次”，处理低分、并列、过期和数据不足；不称命中概率。
  5. 因素卡先用口语标题；明确区分搜索地点和收藏地点；提供可关闭、可重看的轻量提示。

验收：列表日期可辨；场次切换同步所有上下文；缺测不被解释成晴朗；全部偏低不强行推荐；搜索不自动收藏。

工作量：中。将解释和比较规则独立于 UI，便于核对与维护。

Factor cards follow the next forecast, while the sky defaults to now. Event selection exists, but live/preview context is subtle; collapsed rows can look like a shorter forecast.

  1. Group sunrise and sunset events by date and label the four-day coverage.
  2. Keep sky, factors and summary in sync with the selected event; label preview and offer “Now”.
  3. Generate a rule-based synthesis from existing model factors; explain disagreement and missing data.
  4. Add notable events and handle low, tied, expired and incomplete forecasts without claiming probability.
  5. Use plain labels, clarify search versus save, and provide dismissible replayable hints.

Acceptance: dates are clear; event context stays in sync; missing data is not described as clear weather; low ratings are not forced into recommendations; search does not save automatically.

Size: Medium. Keep explanation and comparison rules separate from UI components.

0.3 · 本地与探索Local and Explore

01
本地

默认路径，保留当前位置、收藏地点和快速搜索。模式存在本机，不要求用户声明身份。

02
探索

选城市，按海边/公园/山顶等类型及朝霞/晚霞筛选。候选卡展示区域、类型、适用时段和资料状态。

03
临时查看与收藏

选中一个地点后进入现有详情预报，标明“临时查看”；点收藏才加入本地列表，返回后保留城市筛选。

数据规则：观赏点保留独立 ID、坐标系、来源和核验日期；缺坐标点不提供地图、距离或路线；用户端标签使用易懂措辞。首期只对选中的一个地点请求完整预报，不对每城 15 点同时拉取天空、风场及双模型数据。

验收：模式切换不清收藏；点位可搜可筛；临时查看不进入常用地点；缺坐标点不会伪造位置；详情返回保留探索条件。

工作量：大，涉及目录接入、列表体验、路由状态及收藏去重。

01
Local

Default path with current location, saved places and quick search. Remember the mode locally; do not ask users to classify themselves.

02
Explore

Select a city, then filter by coast, park, hilltop and sunrise/sunset. Cards show area, type, event fit and evidence state.

03
Preview and save

Open one candidate in the existing forecast page as a temporary view. Save only on explicit action and restore city filters on return.

Data rules: Keep stable IDs, coordinate system, sources and review date. No map/distance/route for unresolved coordinates. Fetch a full forecast only after a single place is selected, not for all 15 city candidates at once.

Acceptance: switching preserves saved places; candidates can be searched and filtered; previews are not auto-saved; unresolved coordinates are never invented; returning restores Explore state.

Size: Large: catalog integration, list UX, route state and deduplication.

0.4 · 远期趋势Long-range trend

不要直接把 `FORECAST_DAYS` 改成 14：当前天气、风场、气溶胶时效不同，且按现有耦合方式请求 8 天空气质量曾返回 HTTP 400。API 接受较长参数也不代表所有因素都有完整远期预报。
Do not simply set `FORECAST_DAYS` to 14. Weather, wind and aerosol horizons differ; the current coupled request for eight air-quality days returned HTTP 400. An accepted API parameter does not prove complete long-range coverage.
  1. 建立逐日覆盖矩阵：云模型、降水、三个风层、AOD、小时插值边界、跨午夜和失败响应。
  2. 制定缺测规则；远期数据不完整时明确标记趋势和缺失因素，不照常显示完整火烧云等级。
  3. 先评估短期延长，验证用户是否用它安排周末；14 天另做产品决策。
  4. 会员范围、价格和社群福利单独验证；在用户查看更多日期/周末/附近地点等自然触点介绍。

工作量：覆盖验证中等，短期趋势实现大；14 天产品化暂不估期。

  1. Build a daily coverage matrix for cloud models, precipitation, three wind layers, AOD, hourly boundaries, midnight and error cases.
  2. Define missing-data behavior. Incomplete long-range data must not appear as a complete glow rating.
  3. Evaluate a shorter extension and whether people plan around it; make day 14 a separate decision.
  4. Validate supporter scope, pricing and community value separately; introduce it at relevant moments.

Size: Medium for coverage validation, large for a short extension. Day-14 productization is unestimated.

0.5 · 周边比较与用户共建Nearby comparison and community input

分开回答天气、视野、距离与路线。天气评分来自坐标和模型；观赏适用性来自方向、遮挡、照片与实地核验；路线与开放时间需要可靠数据源。首期在小范围比较同一场朝霞/晚霞，展示距离、模型分歧、数据完整度和地点核验状态。批量摘要与缓存稳定后再扩展。

用户提交地点后进入审核队列，检查同名地点、坐标系、来源许可、开放状态、朝晚霞方向及核验时间。未经授权不批量抓取社交平台；热度数据和天气质量分开记录。

验收：比较对象是相同日期/场次；低分或差距小时如实显示；未经审核的投稿不公开；路线/票价/营业时间仅来自可靠且可持续更新的数据源。

工作量：中到超大，依赖批量天气摘要、缓存和内容审核闭环。

Answer weather, view quality, distance and route separately. Weather comes from forecast models; viewing suitability needs direction, obstruction and field review; routes and access need reliable sources. Start with a small same-event comparison showing distance, model disagreement, completeness and evidence status. Expand only after batch summaries and caching are stable.

Submissions enter review for duplicates, coordinate system, source rights, access, event direction and review date. No unauthorized bulk social scraping. Popularity is kept separate from forecast quality.

Acceptance: compare the same date and event; report low or similar outcomes honestly; unreviewed submissions stay private; route and access facts come from reliable maintainable sources.

Size: Medium to XL, dependent on batch summaries, caching and moderation.

体验指标：预报点选率、搜索后查看率、临时查看转收藏率、探索筛选到详情转化、回到本地的上下文保留率。

质量指标：坐标覆盖率、直接观霞来源占比、地点信息核验新鲜度、预报字段完整率、模型分差和用户实测反馈。社交互动量另行记录。

主要风险：地标坐标被误当机位；分数被说成概率；重复全量请求造成开销；远期缺测被当好天气；浏览自动加入收藏；过期开放信息影响出行。

Experience metrics: event selection, search-to-forecast, preview-to-save, Explore filter-to-detail and context retention when returning Local.

Quality metrics: coordinate coverage, direct viewing evidence, freshness of access facts, forecast completeness, model spread and user observations. Track social engagement separately.

Key risks: landmark mistaken for a camera position; score mistaken for probability; repeated full requests; missing long-range data mistaken for good weather; previews auto-saved; stale access facts affect trips.

建议暂不做：14 天完整等级承诺、全城候选点同时拉完整预报、用热度代替天气、把本地/探索与会员收费绑定。Defer: guaranteed 14-day ratings, full forecasts for every city candidate, popularity as weather quality, and tying Local/Explore to payment.
