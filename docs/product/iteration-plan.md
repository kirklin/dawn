# Twilit 产品迭代方案

**整理日期：** 2026-10-15
**范围：** 依据用户反馈截图、当前仓库实现及首批观赏点数据，规划预报体验、本地/探索路径、预测窗口和周边推荐的迭代顺序。

## 建议结论

先交付一次“看得懂、选得准”的预报体验迭代，再接入“本地/探索”两条地点路径。随后验证延长预报的实际数据覆盖，最后建设附近观赏地比较和用户共建。这样每一步都能在真实用户面前验证一个完整价值，不会同时引入远期天气、地点审核、批量请求和会员机制等多个未验证变量。

当前基础已包括未来 4 天朝晚霞预报、WebGL 天空、四类影响因素、地点搜索和本地收藏。首批观赏点库为 15 城 × 15 点，共 225 个候选；208 个有参考地标坐标，17 个坐标未确认，50 个点的观赏用途主要是地形推断，所有点都尚未实地核验。**目录整理完成不代表地点推荐功能已上线。**

## 0.2：看懂一场霞

### 要解决的问题

目前因素卡会跟随下一场预报，而天空默认跟随当前时间。用户可以点击预报行切换天空，但页面尚未始终明确说明正在看实时天空还是某场预报；因素说明也没有汇总成一句综合判断。列表折叠部分场次后，用户还可能把“可见场次”误以为预报天数。

### 交付范围

1. **按天列出未来场次**：标题明确“未来 4 天”，按日期分组，每天分别标朝霞/晚霞；已过场次不显示时，覆盖范围仍清楚。首屏保留简洁样式，展开后能查看完整日期。
2. **统一场次上下文**：点选一行后，天空、因素卡、综合结论同步到该场；显示日期、朝/晚霞、时间与“预报预览”。实时天空显示“现在”，提供“回到现在”。
3. **增加综合结论**：用确定性规则从已有双模型评分因素生成“机会等级 + 主要限制/有利条件 + 建议”。模型分歧明显时写明分歧；关键数据缺失时写明缺测，不将缺测解释为晴朗。
4. **增加“值得关注的场次”**：在现有四天事件中比较可用场次，允许只看朝霞或晚霞。低分、并列、已过期和模型差异均有独立状态；文案称“预测评分较高/值得关注”，不称“命中概率”或保证最佳。
5. **降低理解成本**：因素卡将生活化问题放前面，专业名称和数值保留；搜索用“搜索地点/查看预报”，收藏用“收藏地点”。增加可关闭、可重看的搜索、选场次和拖动太阳提示。

### 验收标准

- 用户能从列表辨认真实覆盖日期及每天朝霞/晚霞；展开/收起不会造成预测天数误解。
- 选择任意场次，天空时刻、标题、因素与解释都指向同一场；回到现在后恢复实时上下文。
- 少云、光路受阻、头顶低云、气溶胶、降雨、模型分歧和缺失数据都有合理说明；没有把模型分数描述为历史概率。
- 全部场次偏低时显示“近期机会偏低”，并列时不硬排第一；缺少数据时不生成伪精确结论。
- 搜索城市只打开详情；只有明确点击收藏才加入常用地点。

**相对工作量：M。** 主要改动在预报卡、页面状态、因素说明和中文文案；综合解释与场次摘要应做成独立、可审阅的规则函数。

## 0.3：本地与探索

### 导航与本地路径

在地点列表页顶部放一个轻量切换：**本地｜探索**。默认“本地”，保留当前定位卡、收藏地点列表、快速搜索。切换状态可存在本机浏览器中，用户无需注册或填写“本地用户/游客”身份。

### 探索路径

探索页先选择城市，再浏览观赏点。首期可按已有 15 城目录展示城市搜索/选择器，并提供类别、朝霞/晚霞筛选。卡片显示名称、区域、类型、适用时段及资料状态；机位和开放状态未经核验时明确标注。

用户点开一个候选地点后，进入现有地点预报详情页，显示“临时查看”；页上的独立收藏按钮加入本地列表。用户返回后仍回到此前选择的城市和筛选条件。未收藏地点不加入本地列表，也不因浏览而覆盖“我的位置”。

### 数据接入规则

- 将观赏点目录作为独立、版本化的应用数据接入，不把完整数据直接塞进地点搜索 API。保留稳定 `id`、城市、类别、朝晚霞适用性、来源、坐标系、坐标状态和核验日期。
- 17 个待确认坐标的点可留在人工数据维护界面，但暂不提供地图定位、距离或路线入口；名称搜索可按产品决定是否显示“位置待核实”。
- 用户界面不用 A/B/C 证据等级，改用“公开资料提到观霞”“旅游资料提到”“根据地形初步整理”等解释性标签；“机位待核实”和“开放信息待核实”单独显示。
- 选中一个地点后再请求完整预报。首期不对当前城市 15 个候选同时请求 `getPlaceForecast`，避免重复计算每个点及朝晚霞光路、风场和模型数据。
- 收藏现有结构储存在 `localStorage`。首期可以继续复用 `SavedPlace` 的坐标收藏；来源目录 ID 可用于去重和显示来源，但不强制更换全部既有收藏数据。

### 验收标准

- 本地路径保留定位、已收藏地点和既有快速查看流程；模式切换不清空任何收藏。
- 探索路径可按城市和朝/晚霞查到目录里的有效地点；点开后能看现有完整预报。
- 临时查看和收藏是两个明确动作；收藏后地点出现在本地列表，取消/删除后探索目录仍保留。
- 缺坐标点不会生成地图点、距离或机位；目录证据标签不会被理解成效果保证。
- 城市筛选状态能在查看详情后返回并保留。

**相对工作量：L。** 除页面外，还需确定目录 schema 与打包方式、城市浏览状态、目录 ID 与收藏去重规则，以及现有搜索直达详情的回退行为。

## 0.4：延长预报窗口

截图提出精神股东/支持者可查看最多 14 天趋势、最佳关注日期、周末提示和扩展分析。产品方向有价值，但目前的计算链路不能直接把 `FORECAST_DAYS` 改成 14：云量、风场和气溶胶来源的有效覆盖不同；现有气溶胶请求范围还与天气窗口耦合。此前代码核对记录显示，按 `FORECAST_DAYS + 1` 请求 8 天空气质量会收到 HTTP 400；即使某个 API 接受较长时间参数，也不代表 CAMS 提供完整的远期 AOD。

### 建议顺序

1. 先完成一份数据覆盖矩阵：按预报日检查两种云模型、降水、三个风层、AOD 和每小时插值边界，覆盖跨午夜及请求错误。
2. 定义缺测口径：远期若缺 AOD 或其他主因素，页面显示“趋势参考/部分因素缺失”，不把缺测默认作空气清澈，也不照常渲染成完整确定等级。
3. 若天气、风场、评分方法可支持，先考虑较短的延伸趋势试点，再观察用户是否真的因此规划周末出行；14 天作为第二个产品决策点。
4. 会员方案单独验证：免费范围、支持者范围、价格与社群福利需要用户研究和成本测算；不在首页强制弹窗。到达第 4 天、点查看更多日期、查看周末或周边地点时再解释支持者价值。

### 验收标准

- 每个日期可解释数据覆盖和缺失因素，远期标签、模型差异和可信程度不会被误认为命中概率。
- 缓存跨午夜、边界插值、缺字段和来源超出时效均有明确处理。
- 会员功能在真实数据能力和成本确定后发布；不以“14 天”作为准确性承诺。

**相对工作量：技术验证 M，短期趋势实现 L，14 天产品化 XL/待评估。**

## 0.5：周边比较与用户共建

### 周边观赏地

分开回答“附近天气更有利吗”和“这个地方视野/开放条件好吗”。天气分数来自地点坐标及预报模型；视野适用性来自方向、遮挡、现场照片和实地核验；距离与路线来自地理和路线服务。不要揉成单一“最佳”分数。

从一个城市或用户附近的少量候选开始，先做相同朝霞/晚霞场次对比，展示地点、距离、分数差异、模型分歧、数据完整度及观赏资料状态。批量摘要接口与缓存稳定后再扩大候选数量。当前 `/api/forecast/summary` 仍调用完整地点预报，所以不能按每个点重复请求它来做周边扫描。

### 用户共建

用户提交城市、地点名、地图链接/坐标、类型、适合朝霞/晚霞、视野说明和来源；进入待审核队列。人工核对同名异地、坐标系与来源、可进入性、视野方向和最近核验时间后再发布。未经明确授权，不批量抓取小红书等社交平台。讨论热度只能是独立的辅助字段，不能替代观赏证据或天气预报。

### 验收标准

- 同一场次对比的是同一日期和朝/晚霞，地理距离、模型分歧和数据完整性同时可见。
- 低分或差距很小时如实显示“近期整体机会偏低/与本地差异不明显”，不为转化强推路线。
- 用户提交未经审核不会直接进入公开目录；通过审核的改动保留来源、审核人/状态及时间。
- 路线时长、票价和开放时间只在有可靠且更新周期明确的数据源后显示。

**相对工作量：M–XL。** 需要批量天气摘要与缓存、可访问的地点资料审核流程、以及路线/营业信息来源策略。

## 建议排期门槛

不绑定具体日历周期，按可验收的里程碑推进：

| 里程碑 | 完成条件 | 再进入下一阶段前确认 |
| --- | --- | --- |
| M1：预报易理解 | 0.2 验收标准通过；选场次后上下文一致 | 通过内部走查及至少一轮新用户可用性观察 |
| M2：探索可用 | 0.3 支持 15 城目录浏览、地点详情和显式收藏 | 坐标状态、来源标签、城市返回状态无误；先完成一批重点点位人工复核 |
| M3：远期可解释 | 数据覆盖与缺测规则通过技术评估；用户理解趋势标签 | 再决定免费与支持者日期范围，尚未满足则继续保持现有 4 天 |
| M4：区域推荐可信 | 少量候选对比与缓存测得可控，地点资料有审核闭环 | 再扩大到全目录或开放用户投稿 |

## 指标与风险

**体验指标**：用户点选预报场次的比例；搜索后直接查看预报的比例；临时查看转收藏比例；探索页城市/类别筛选到详情的转化；返回本地时列表和上下文保留率。

**质量指标**：有效坐标覆盖率；有直接观霞证据的点占比；近期地点开放信息的核验日期覆盖；预报字段完整率、两模型分差和用户观测反馈。社交互动量独立记录。

**主要风险**：把地标中心当作具体拍摄机位；把预测等级说成天气命中概率；为比较地点发起重复且昂贵的全量预报请求；远期缺测被误解为好天气；把游客临时查看强制写进首页收藏；靠无法持续更新的票价/开放时间误导出行。

## 暂不进入首发范围

- 不把 225 个候选点都标为“最佳机位”或“实地验证”。
- 不为城市列表里每个地点一次性加载完整天空轨迹。
- 不在数据时效未经验证前承诺 7 天或 14 天的完整火烧云等级。
- 不以社交讨论量代替天气质量、地点视野或真实观测。
- 不将本地/探索模式与会员收费绑定。
