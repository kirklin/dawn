0.2 · 看懂一场霞Understand a glow

建议优先：按天展示朝霞/晚霞；同步天空、因素和结论的场次上下文；增加综合解释、值得关注场次、口语指标和轻提示。Suggested priority: events by day; consistent sky/factor/summary context; synthesis, notable events, plain-language labels and hints.

价值：用户知道何时看、为什么这样判断。待确认：规则解释如何处理双模型分歧与缺测？首版引导做到什么程度？Value: tell users when to look and why. Open: how should rules handle model disagreement and missing data? How much onboarding belongs in the first release?

0.3 · 本地与探索Local and Explore

地点列表提供本地/探索切换；浏览城市观赏点；打开单点预报后明确选择是否收藏。Add a Local/Explore switch, browse city viewpoints and keep forecast preview separate from saving.

价值：兼顾熟悉本地的用户与出游用户。待确认：首批开放哪些点？17 个缺坐标点如何处理？哪些点要先人工复核？Value: support both local viewing and trip planning. Open: which points launch first? How should 17 unresolved coordinates be handled? Which candidates need review?

0.4 · 远期趋势Long-range trend

验证数据时效和缺测策略后，再决定是否延长当前四天预报或提供支持者趋势。Evaluate data horizons and missing-data policy before extending the four-day forecast or offering supporter trends.

价值：提前安排出行。待确认：云量、风场、AOD 实际覆盖与维护成本；14 天表达是否可信。已知空气质量 8 天请求曾返回 HTTP 400，简单改配置不可行。Value: plan trips ahead. Open: actual cloud, wind and AOD coverage, upkeep cost and credible day-14 language. An eight-day air-quality request previously returned HTTP 400; a config change alone is insufficient.

0.5 · 周边比较与用户共建Nearby comparison and community

比较少量附近候选的同一场次；分开展示天气、视野、距离和开放情况；用户地点经过审核再入库。Compare a small set of nearby candidates for the same event; separate weather, view, distance and access; review contributions before publishing.

价值：回答附近哪里更值得看，持续补充地点库。待确认：批量预报与缓存成本；谁审核来源/坐标/开放信息；路线数据来源。Value: find nearby options and improve the catalog. Open: batch forecast and cache cost; moderation ownership; reliable route and access sources.
